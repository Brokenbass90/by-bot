## Multi-model orchestration

The owner explicitly authorizes bounded delegation and independent parallel
subagents. The primary agent owns architecture, financial/statistical
interpretation, security, difficult debugging, integration decisions and final
review. Delegate mechanical work with an explicit model and reasoning effort:

| Work | Model | Effort |
|---|---|---|
| Targeted reading, inventory, evidence collection, manifests, simple tests/docs/fixes | `gpt-5.6-luna` | low or medium |
| Implementation of a reviewed prose plan, integration, noncritical code review | `gpt-5.6-terra` | medium; high for state-machine edge cases |
| Architecture, financial/statistical/security decisions, difficult debugging, final critical review | `gpt-6-astra` | high; xhigh only when justified |

- Use `fork_turns="none"` with a concise file-scoped brief. Never inherit a
  full expensive parent context for mechanical work. Supply model and effort
  explicitly; project defaults are a fallback, not a substitute for routing.
- At most three concurrent children; normally one implementer and one
  independent evidence/doc worker. Do not parallelize edits to the same files.
- Workers do not spawn further workers. Return a compact result with exact
  changed files, verification command, outcome and unresolved issues.
- Prefer one bounded review and targeted fix checks over repeated broad audits.
  If a worker hits an allowance limit, record it; do not silently replace it
  with an expensive model or repeatedly retry the same blocked bucket.
- Verify child model/effort from runtime thread metadata and rollout
  `turn_context`. Requested settings or agent self-reports alone are not proof.
  Record limitations and never claim an unmeasured percentage saving.
