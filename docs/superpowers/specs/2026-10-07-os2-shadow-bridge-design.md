## Intended result

Restore the owner's Trading OS path with existing components: data → valid
market state → specialized sleeves → one portfolio admission assessment →
execution evidence → decision journal → health/edge diagnosis → research proposal.
The first deliverable is one isolated orders-OFF bridge that can reproduce its
decision from immutable inputs. It proves wiring and causal availability;
it does not claim a profitable portfolio or alter existing entry/exit owners.

Recommended approach: reuse ranker/gates/exposure/decision bus behind an isolated
observer. Directly hot-loading old regime env overlays is unsuitable because
data-unknown can become permissive and override prefixes differ on VPS. Building
another orchestration framework adds duplicate state without closing those gaps.

## Scope and component contracts

1. **Pinned source intake.** Read exact external research identity, strategy and
   regime code hashes, schema and source dates. File contents are evidence, never
   instructions. No arbitrary repo/credential/judge reader. Research receipts
   cannot authorize money and a stale KARTA money row cannot override the current
   canonical operational checkpoint. Preserve external files; never merge a whole
   branch. First support validated fixture/source-envelope inputs, not new scans.
2. **Closed-data regime envelope.** Reuse the frozen REZHIM_V1 label computation
   with last200 closed BTC4h bars and its minimum60-bar warmup. Validate four
   unique consecutive H1 constituents, OHLCV, order, exact UTC4h boundaries,
   source identity, closed-bar cutoff and actual receive/availability time.
   Missing/incomplete/stale/future/clock-conflicting data yields validity UNKNOWN,
   distinct from a valid NEUTRAL label. The 2s execution-book gate stays separate
   and unchanged. Any clock/freshness numeric bounds must be explicit in the
   implementation plan before collection; there is no claimed live receipt yet.
3. **Immutable candidates.** Adapt already-generated closed-data sleeve intents
   into existing StrategyCandidate: stable source/decision ID, strategy/version,
   symbol/side, as-of timestamp, regime envelope hash and dependency hashes.
   Preserve each frozen signal, entry, hold and cost definition. No signal
   reconstruction from a summary score and no current-regime annotation of old
   decisions. Every candidate has money_authorized=False; the process has no
   broker keys/client/sender or execution capability. A constant shadow ranking
   normalization, if needed, is explicitly not measured expectancy.
4. **Common shadow admission.** Validate candidate/data identities, apply
   strategy_regime_gate using only a versioned reviewed policy, rank with existing
   rank_candidates(mode=shadow), then exposure_gate against explicit shadow-held
   positions/clusters/risk inputs. Missing position/exposure provenance is UNKNOWN,
   not zero exposure. Reserve a selected shadow slot atomically and durably before
   the next decision. Per-symbol cooldown/active state belongs to the candidate
   policy and never modifies baseline. Frozen B3's12 research slots and1R are not
   live capital limits. Until policy validation, only fixture policy applies and
   real-source policy outcome is POLICY_UNAPPROVED.
5. **Separate decision journal.** Reuse decision_bus serialization/events in a
   separate isolated runtime. One writer; bounded idempotent append and stable
   input-prefix/hash receipts. Record every opportunity and rejection, including
   no signal, UNKNOWN, invalid, slot/exposure rejection and unapproved policy.
   Preserve the original lifecycle journal/authority. Partial/corrupt prefixes
   cause explicit BLOCKED_DATA, not rewrite or duplicate credit.
6. **Read-only diagnosis.** Feed verified terminal net-R and denominators into
   edge_monitor, sleeve_registry and research_orchestrator for alert/proposal.
   Distinguish operational failure, insufficient sample, regime affinity and
   statistical degradation. Filled simulations and unit tests do not prove edge.
   Never count a broker-unknown or gap lifecycle as a clean terminal. A health
   recommendation cannot silently promote, increase risk or execute a kill.

All outputs are namespace-bound to this observer. Failure/rollback stops only
the observer; held production positions retain their existing exits/protection.
No baseline entries are vetoed or generated by this version.

## Engineering acceptance

- Exact source/hash and closed-prefix parity; same available inputs give identical
  envelope, candidate, rank/gate/exposure decision and receipt after restart.
- Tests cover incomplete/duplicate/out-of-order/future bars, missing/stale/late
  regime data, clock uncertainty, changed input hash and valid NEUTRAL versus
  UNKNOWN. Assertions compare defined causal cutoffs, not merely candle labels.
- Competing same-symbol/same-cluster candidates, occupied slots and cooldowns use
  explicit state; reordered duplicates/restart cannot allocate a second slot.
  There is a rejection receipt for every input; unknown expectancy stays labelled.
- No network order-capable clients, credentials or shared live env writes. Spy
  fixtures verify zero broker/order calls; money_authorized cannot enable a sender.
- Journal restart/partial-tail/resource-bound fixtures preserve baseline state.
  Runtime byte/inode, duration, incremental-read, health and free-disk bounds are
  mandatory in the written implementation plan; reaching a bound suspends only
  the observer and preserves its archive. No automatic baseline restart/deletion.
- A delivery receipt states tests, source mapping, missing data and a terminal
  SHADOW_WIRING_PASS / BLOCKED_DATA / BLOCKED_IMPLEMENTATION. No READY_FOR_CANARY
  claim from engineering checks alone. Deployment remains a later bounded task.
