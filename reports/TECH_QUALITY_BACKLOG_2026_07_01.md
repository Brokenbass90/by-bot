# Технологии качества — что ещё дописать (2026-07-01, Claude)

Помощники-детекторы уже есть (range_filter, retest_quality, breakout_confirm,
pump_exhaustion, elder_filter, market_context). Они улучшают ВХОД. Ниже — чего не
хватает для качества торговли в целом, по приоритету пользы/риска.

## P0 — прямо бьёт в нашу главную боль (оверфит)
1. **OOS-plateau selector / WF-харнесс (модуль).** Кодифицировать дисциплину отбора:
   на вход — результаты свипа по окнам; на выход — ранжирование по OOS-СТАБИЛЬНОСТИ
   (медиана+разброс по фолдам, штраф за один-окно-герой), авто-ОТКЛОНЕНИЕ PF-пиков.
   Почему P0: именно ручной отбор по in-sample пику дал 8 месяцев «красивых цифр».
   Пока это в головах и текстах — будет повторяться. Чистый, тестируемый, без сервера.
2. **Slippage в forex/engine.py** (крипта уже честнее). Без него FX-цифры оптимистичны.

## P1 — качество риска и исполнения
3. **Vol-targeted position sizing (модуль).** Размер позиции из ATR/волатильности так,
   чтобы риск на сделку был стабильным в R (не в %), с cap и полом. Сейчас риск задан
   грубым risk_pct — из-за этого R-разброс большой. Прямо улучшает Sharpe/DD.
4. **Maker-limit-at-level executor (helper).** Лечит корень провала InPlay — поздний
   вход по закрытию. Ставить лимит У уровня (maker), контролировать неисполнение/частичное,
   мерить entry-slippage vs уровень. Лучше фактические филлы -> больше R.
5. **Корреляционный/exposure-гейт (портфель).** Не набирать 3 коррелированных лонга
   (cross_sectional.py есть — довести до жёсткого гейта на суммарную бету/кластер).

## P2 — мониторинг живого эджа (ИИ-обвязка)
6. **Live expectancy / edge-decay монитор.** Трекать реализованный R vs бэктест по
   каждому рукаву; ранний флаг, когда live расходится с ожиданием (до просадки),
   кормит strategy_breaker и ИИ-аналитика. Сейчас breaker — постфактум по PnL/серии;
   монитор ожидания ловит деградацию РАНЬШE.
7. **Унифицированный feature-слой для крипты** (funding/ликвидации/плотности) — когда
   данные стабильны; кормит и directional-фильтры, и carry/pair-arb.

## Рекомендация
Следующим строить **#1 (OOS-plateau selector)** — он дешёвый (модуль+тесты, без сервера),
и это единственная технология, которая напрямую предотвращает повтор нашей главной
ошибки. Потом #3 (sizing) и #4 (maker-executor) — качество риска и филлов.

## Принцип
Технологии — в рельсах: помогают дисциплине (OOS, R:R, честные издержки, стабильный риск),
а не добавляют степеней свободы для оверфита.
