# САМОУСОВЕРШЕНСТВОВАНИЕ + ЗАЩИТА ОТ РЕГРЕССИИ (2026-07-03, Claude)

Дополнение к LIVE_MANAGEMENT_LOOP_BLUEPRINT (там — петля исполнения). Здесь — два контура,
которые делают бота охотником, не деградирующим со временем: (I) оборона в глубину от
регрессии, (II) маховик самоусовершенствования, (III) как именно используется ИИ на борту.

## I. ЗАЩИТА ОТ РЕГРЕССИИ — 5 слоёв (каждый ловит свой класс поломок)

L1 КОД: 737+ юнит-тестов = регрессия-сетка. Правило деплоя: полный прогон зелёный ->
  фича за флагом default OFF -> деплой мёртвым кодом -> сутки стабильности -> включение
  флага -> rollback = выключить флаг. Одно изменение за раз. Нарушений не бывает.
L2 ДАННЫЕ: candle_coverage + cost_feasibility перед КАЖДЫМ прогоном и в live-forensics.
  Ловит класс «стратегия невиновна, данные врут» (2 случая за 2026-07-03).
L3 СТРАТЕГИЯ (live): canary tiny -> breaker (авто-стоп по PnL/стрику) -> canary expiry
  (жёсткий срок, продление руками) -> edge_monitor (decay: healthy/watch/degraded/halt).
  Распад эджа режется ДО просадки, а не после.
L4 ПОРТФЕЛЬ: smart_risk (анти-мартингейл: в просадке/degraded/high_vol РЕЖЕМ),
  exposure_gate (correlation-cap: коррелированные short-рукава не задваиваются),
  regime_hmm-гейт (bear-зависимые рукава выключаются в bull), hard_cap риска <= 1%.
L5 ПРОЦЕСС: пре-регистрация порогов ДО прогона (нельзя двигать ворота под результат),
  OOS+cross-symbol+side-split обязательны, ledger = единая память (решения не теряются
  между сессиями/чатами), live-vs-backtest parity monitor (сделки live сверяются с
  ожиданием бэктеста — ловит расхождение исполнения).

Смысл слоёв: L1 ловит баг кода, L2 — гнилые входные, L3 — умерший эдж, L4 — системный
риск, L5 — самообман человека/ИИ. Регрессия должна пробить ВСЕ пять, чтобы дойти до денег.

## II. МАХОВИК САМОУСОВЕРШЕНСТВОВАНИЯ (замкнутый цикл, крутится сам)

  [1] decision_bus: каждая live/shadow сделка пишет контекст (режим/фильтры/риск) + исход
   -> [2] ИИ-МАЙНЕР (еженедельно, в рельсах): читает bus, ищет паттерны — «фильтр X поднимает
      expectancy», «символы класса Y тянут вниз», «в режиме Z эджа нет» -> ГИПОТЕЗЫ
   -> [3] каждая гипотеза = A/B на OOS (wf_folds+oos_selector+cross-symbol), НЕ мнение
   -> [4] research_orchestrator компонует Proposal: PROMOTE/DEMOTE/HOLD рукавов, новые
      кандидаты из shadow, retest-очередь -> TELEGRAM владельцу
   -> [5] владелец жмёт да/нет -> Codex применяет одно изменение за флагом
   -> [6] canary/A-B замер -> технология ЗАСЛУЖИЛА включение результатом или вернулась в ящик
   -> обратно в [1], уже с новой атрибуцией.

Так «все технологии» вписываются НЕ разом, а по заслугам: каждый модуль из ящика (26+)
получает шанс через гипотезу майнера или ручную идею, и проходит тот же станок. Включённое
без результата — демоутится. Это и есть самоусовершенствование: бот сам генерирует
кандидатов на улучшение себя, но каждое улучшение доказывается до денег.

Охота за деньгами = тот же маховик на входе: постоянный теневой поиск (свипы по нашим
козырям: liq/OI/funding H4, FX-структура, частые механич. паттерны) -> preflight ->
гейты -> кандидаты в Proposal. Бот непрерывно ищет новые рукава, пока живые торгуют.

## III. ИИ НА БОРТУ — 3 яруса по скорости решения (качество = правильный ярус)

БЫСТРЫЙ (каждый бар, миллисекунды): НИКАКОГО LLM. Код-рельсы: сканеры, гейты, sizing,
  breaker. Детерминировано, тестируемо, дёшево. LLM здесь = медленно, дорого, недетерминир.
СРЕДНИЙ (час-день): edge_monitor, parity, аномалии -> алерты в TG. Код считает, ИИ(LLM)
  привлекается на РАЗБОР аномалии (прочитать bus, предложить гипотезу), не на решение.
МЕДЛЕННЫЙ (неделя): research_orchestrator + ИИ-майнер гипотез + Claude-разборы (как этот
  чат) -> Proposal владельцу. Здесь LLM максимально полезен: синтез, атрибуция, дизайн
  экспериментов. РЕШАЕТ человек.

ГРАНИЦА (нерушимо): ИИ никогда не крутит параметры стратегий в live напрямую. ИИ двигает
риск/режим/жизненный цикл В РЕЛЬСАХ и ПРЕДЛАГАЕТ изменения логики через гейты. Свободная
самооптимизация на live-данных = автоматизированный оверфит = слив с ИИ-ускорением.

## Статус и порядок включения маховика
1. [сейчас] Спек wiring decision_bus+edge_monitor в ATT1 у Codex — это узел [1]+[2]-вход.
2. [+рукав 2] Та же обвязка второму рукаву, exposure_gate между ними.
3. [2-3 рукава] research_orchestrator в scheduled -> первый еженедельный Proposal в TG.
4. [после 4-6 недель bus-данных] ИИ-майнер гипотез по накопленной атрибуции (узел [2]).
5. [постоянно] Теневой поиск фоном; ledger; пре-регистрации.
Маховик частично уже крутится вручную (этот чат = узлы 2-4 руками). Wiring делает его
автоматическим; человек остаётся на аппрувах.
