## Решение (версионированное, история не переписывается)
1. **Исследованная геометрия рукава = f1 0.55.** Именно на ней получен DEV_PASS. Переход на 0.50 был бы сменой параметра
   без свидетельства — запрещено (не настраивать замороженное).
2. **Адаптер берёт f1 из контракта (константа 0.55), а не из записи продюсера.** Поле `geom.f1` продюсера — информационное:
   сохранять в квитанции как `f1_istochnika`, при расхождении писать `F1_SOURCE_MISMATCH_INFO`, решение НЕ отвергать.
3. Все остальные поля geom (stop_x 4, max_lev, stop_dolya, rr1, rr2, bar_ts_*) проверяются как раньше — расхождение = отказ.
4. **Продюсер не меняется.** `ten.py` пишет правду о стратегии; правка сломала бы непрерывность тени и окна 900.
5. Следствие для проверки паритета движков (окно 900): исходы тени посчитаны с f1 0.50, история — с 0.55. Сравнивать
   только при одинаковой доле: пересчитать CONTROL-исходы тени движком `yadro.prodvinut` с f1 0.55 по тем же входам.

## Величина эффекта (арифметика, без прогона)
При k1 0.25 / k2 0.5 разница 0.55 против 0.50 есть только у сделок, взявших TP1: TP1→TP2 −0.0125R, TP1→стоп +0.0625R,
TP1→время — между ними. Стоп до TP1 (большинство убыточных) — без разницы. Это не меняет вердикт, но обязано совпадать с контрактом.
