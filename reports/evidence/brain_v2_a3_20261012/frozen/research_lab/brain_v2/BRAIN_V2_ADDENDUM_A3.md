# BRAIN_V2 — дополнение A3: временной контракт жизненного цикла (12.10.2026, Claude). Без подбора параметров.

Проблема (Codex): A1 группировал пакет по floor(t_available) к часу, а ETS2/SF3 становятся известны в :15/:30/:45; вход next-open
мог бы оказаться РАНЬШЕ конца пакета → решение «знало бы» возможности, пришедшие позже входа. A3 заменяет правило пакета A1 §1
(только часть «пакет = час»); лимиты, порядок, числа — без изменений. PnL рук до A3 не считался, исходы не прочитаны.

## 1. Часы решений
Единые часы всех трёх рук — сетка 15 минут (наименьшая база ног). **Пакет τ = все возможности с t_available == τ точно**
(t_available по A2: ts + длина бара базы; для H1-ног τ кратно часу, для 15m-ног — четверти часа).
Возможность, у которой t_available не на сетке 15 мин → отказ `off_grid` (по построению потоков таких нет).

## 2. Порядок событий в тик τ (строго)
1) **Освобождение**: закрыть все позиции с release_time ≤ τ; их net PnL зачисляется в реализованный капитал E руки.
2) **Пакет τ**: сортировка по правилу руки (A1 §1), жадный проход по лимитам (A1 §1, A2 §1) при E после шага 1.
3) **Вход**: принятые позиции входят по цене ОТКРЫТИЯ бара базы, начинающегося в τ (= next-open потока). Никакая возможность
   с t_available > τ не влияет на решения пакета τ.

## 3. Цена, выход, освобождение
- Вход/выход и R — ровно как в потоке B3 (orchestrator.simulate: вход открытием бара в τ, стоп раньше целей, выход по стопу/цели/
  удержанию). Потоки не пересчитываются.
- release_time = τ + hours·1 ч, где hours — поле потока. Для H1-ног это точный момент выхода; для 15m-ног hours = ceil(бары/4) →
  release_time ≥ фактического выхода (не более чем на 45 мин позже; консервативно для лимитов, одинаково во всех руках).
- **Вход и выход в одном часе / одном тике**: допускаются; позиция занимает риск с τ до release_time; если release_time ≤ τ' для
  более позднего тика τ' того же часа — в τ' риск уже свободен (шаг 1 идёт до шага 2). Позиция не освобождается в свой же тик входа.

## 4. Денежный учёт руки (net USD)
risk_usd = r_i (A1 §1); notional = risk_usd · lev (поле потока: цена входа / дистанция стопа).
net_USD = R · risk_usd − 2 · 0.0002 · notional − funding_USD, где R уже включает 6 bps/сторона,
funding_USD = side_sign · notional · Σ ставок по расчётам с τ < t ≤ release_time (лонг платит при ставке > 0, шорт получает).
Ставки — data/pit_daily/<SYM>.json funding (Bybit). Нет ставки для какого-либо расчёта внутри удержания → сделка FUNDING_UNKNOWN:
в руке она остаётся (риск занимает), её funding_USD = 0 НЕ подставляется — сделка исключается из net USD и считается отдельно;
доля таких в любой руке > 5% → развивающий фильтр BLOCKED_DATA.

## 5. Что неизменно
Ячейка/REZHIM/VOL — по floor(τ) к часу (A1 §2, A2 §2): для 15m-ног в :15/:30/:45 используется состояние, известное в начале часа — причинно.
Таблица μ̂/σ̂ — MU_SIGMA_V1 (A2, sha 35fa0e08…), не меняется.
