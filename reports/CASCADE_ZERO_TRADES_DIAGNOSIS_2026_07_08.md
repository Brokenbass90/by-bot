## Два дефекта условий (корень нуля)
1. **`timing` (онсет = 2..5 ПОДРЯД баров с liq>=3x median) = 0% на альтах.** Альт-ликвидации
   приходят изолированными всплесками, а не непрерывной серией по 5m. Требование непрерывного
   ран-а из 2-5 баров почти никогда не выполняется -> JOINT=0.
2. **`liq_pctile>=95` вырождено на разреженных данных.** У большинства баров liq=0, медиана≈0,
   поэтому ЛЮБАЯ ликвидация мгновенно попадает в топ-перцентиль (LINK 63.6%!). Метрика бессмысленна.

## Пре-регистрируемый фикс (2 условия + данные; НЕ трогать остальное)
Заморозить ДО прогона; сравнить с текущей версией на тех же данных; всё в ledger.
1. **Онсет -> ОКОННАЯ интенсивность вместо непрерывного ран-а:** «cascade active», если
   сумма liq-USD за последние `W` баров (W in {3,6}) >= `K` x rolling-mean(liq_usd, 288)
   (K in {5,10}), и `min_bars_in=1`. Убирает требование непрерывной серии.
2. **liq-спайк -> АБСОЛЮТНЫЙ/среднего порог вместо перцентиля-нулей:** гейт по
   liq_usd_bar >= `A` x rolling-mean(288) (A in {8,12}) ИЛИ liq_usd_bar >= абсолютного $-порога
   на символ. Перцентиль на разреженных данных не использовать.
3. **Данные:** держать коллектор ликвидаций running; ре-гонять гейт при накоплении
   >= 60-90 дней. При N<~30 суммарных сделок — «копить поток», НЕ хоронить (правило 07-05).
4. Сетка мини (пре-рег): W{3,6} x K{5,10} x A{8,12} = 12 комбо/сторона, side-split, 4 хроно-фолда,
   coverage/preflight включены. PASS экрана -> строгий wf_folds/oos (как ARF2). Только альты (не BTC/ETH).
