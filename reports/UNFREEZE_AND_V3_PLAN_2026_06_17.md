# Разморозка торговли + перереботанная стратегия v3 (2026-06-17)

Два вопроса владельца: (1) как правильно настроить конфиги, чтобы разморозить торговлю и поднять PnL; (2) сделать правильную переработку стратегий. Этот документ закрывает оба. Переработка стратегии — **сделана в коде** (не ТЗ): `strategies/inplay_retest_v3.py` + тесты `tests/test_inplay_retest_v3.py` (5 зелёных, общий прогон 309 passed).

## 1. Почему сейчас тишина (факт из live-env)
`DRY_RUN=false`, но риск раздан так:
`FLAT_RISK_MULT=0.10`, `SLOPED_RISK_MULT=0.10` — только эти живые;
`IVB1_RISK_MULT=0.0`, `BREAKDOWN_RISK_MULT=0.0`, `ENABLE_RANGE/INPLAY/RETEST/BREAKDOWN_TRADING=0`.
Обвязка не «сломана» — она защищает сильнее, чем зарабатывает. Плюс часть рукавов (IVB1, inplay) логически недоделана: вход после реклейма над rolling-high, а не на ретесте сильного уровня (см. `IVB1_INPLAY_LOGIC_REVIEW_2026_06_16.md`).

## 2. Принцип (честно)
Нельзя вслепую включать всё. Включить сломанный рукав на реальном риске = платить за убыток. Поэтому: **один доказанный эдж ВКЛ > десять полуживых.** Разморозка — тирами, по факту валидации, не по желанию.

## 3. План разморозки (тиры)

### TIER A — включить СЕЙЧАС (реальный, но малый риск)
Единственное семейство с зелёным PASS — **range** (`range v3 r004`). Его и размораживаем:
```
ENABLE_RANGE_TRADING=1
RANGE_RISK_MULT=0.25         # реальный, но малый; рейлы ниже держат просадку
FLAT_RISK_MULT=0.10          # оставляем
SLOPED_RISK_MULT=0.10        # оставляем
# рейлы НЕ трогаем: дневной -2% / общий -5% (portfolio_can_open)
```
Эффект: бот видимо торгует одним проверенным эджем, копятся живые данные. Это и есть «разморозка» без авантюр.

### TIER B — после валидации (в течение этой итерации)
**inplay_retest_v3** (новый, переработанный). Маршрут перед live:
1. auto-research / WF на пакете (см. §5),
2. `backtest/monthly_analysis.py` → красный медвежий месяц = FAIL,
3. `backtest/stack_comparison.py` → голо vs обвязка.
Если чисто → canary:
```
ENABLE_RETEST_TRADING=1
IRV3_ALLOW=<2-3 ликвидные монеты>
# риск 0.2–0.3% на $100 (B-режим)
```

### TIER C — держать на 0 до замены/доказательства
`IVB1_RISK_MULT=0.0`, `ENABLE_INPLAY_TRADING=0`, `ENABLE_BREAKDOWN_TRADING=0`.
Старый IVB/inplay не включаем — их заменяет v3. Breakdown — после собственного monthly-теста.

## 4. Снапшот ≠ live (чинить экспортёр)
`SERVER_SNAPSHOT_latest.md` показывает `safe_config` (напр. `ENABLE_ARS1_TRADING=1`), которого НЕТ в env живого процесса. **Правда для торговли = env живого процесса.** Фикс экспортёра (Codex, scripts): печатать три явных раздела — `.env` файл / overlays / **live-process env** (`os.environ` запущенного бота) — чтобы не было путаницы «что реально торгует».

## 5. Что переработано в коде (v3) и как гонять
`strategies/inplay_retest_v3.py` — реализует подход владельца буквально:
- **реальные уровни:** горизонтальные S/R из кластеров пивотов (`bot.chart_geometry`, ≥2 касания) + **наклонный** уровень из регрессионного канала; НЕ rolling-high;
- **вход НА ретесте-холде:** бар коснулся уровня и закрылся обратно за него (rejection), вход у уровня — не после реклейма;
- **тайтовый стоп** сразу за уровнем (доля structure-ATR);
- **TP перед следующим уровнем** («закрытие перед уровнем») + **раннер** за ним; BE после +1R;
- **минимум фильтров:** сильный уровень + ретест-холд + объём. Всё. (regime-фильтр выключен по умолчанию — именно чтобы не душить частоту.)
- всё через env (`IRV3_*`), подбор без правок кода.

Прогон (Codex, на сервере с полным фидом):
```
# entry_tf должен совпадать с TF баров, которыми харнес кормит maybe_signal
IRV3_ENTRY_TF=15 IRV3_STRUCTURE_TF=60 \
PYTHONPATH=. python -c "from backtest.crypto_multiwindow_wf import run; \
from strategies.inplay_retest_v3 import InplayRetestV3Strategy as S; \
print(run(lambda: S(), 'BTCUSDT', signal_tf='15', regime_tf='60', k=4, fee_bps=10.0, return_details=True))"
```
Затем тот же trade-stream → `monthly_analysis` (медвежий фильтр) + `stack_comparison`. Чисто → TIER B canary.

## 6. Рычаги PnL (без обещаний %)
- один проверенный эдж ВКЛ (range) вместо тишины;
- **maker-входы** (`bot/maker_entry`) — вернуть комиссии, что съедают тонкий эдж;
- v3 ретест-логика → больше и качественнее входов, чем у IVB1;
- param-профили по тирам монет (`bot/param_profiles`).
PnL поднимаем доказанными входами + экономией комиссий, а не увеличением риска на недоказанном.

5. IVB1/старый inplay держать на 0 (заменены v3).
