# Ревью логики IVB1 / inplay-breakout-retest — почему 0 PASS (2026-06-16)

*Анализ исходника `strategies/impulse_volume_breakout_v1.py`. Вывод: стратегии валятся не из-за «рынок эффективен», а из-за логики входа, не совпадающей с проверенным discretionary-подходом владельца.*

## Что делает IVB1 сейчас (по коду)
1. ARM: текущий 5m-бар закрылся выше `prior_high = max(highs[-25:-1])` (скользящий максимум 24 баров) + буфер, при высоком объёме/теле/диапазоне и impulse_pct ≥ min.
2. ENTRY: на последующих барах ждёт ОДИН бар, который (а) низом нырнул в зону отката, (б) закрылся ВЫШЕ уровня + `reclaim_atr` зелёным телом, (в) тело ≥ min. Вход по close этого бара. SL = breakout_level − sl_atr·risk.

## Косяки логики (конкретно)
1. **Уровень = rolling-high 24 баров, НЕ сильный S/R.** Пробой шумового экстремума, а не валидированного уровня с касаниями/наклонной. Главный тезис владельца («правильные уровни») не реализован.
2. **Вход ПОСЛЕ реклейма, а не НА ретесте.** Требуется один бар, который и откатил, и реклеймил уровень — редкость, и вход уже НАВЕРХУ отскока (догон). Правильно: лимитка НА ретесте у уровня.
3. **Стоп широкий и плавающий.** Вход выше breakout_level, SL от breakout_level → risk = (entry−level)+sl_atr·risk_atr. Чем сильнее реклейм, тем шире стоп → плохой RR; затем min/max stop_pct режут сигналы.
4. **Стена фильтров** (macro MACD + regime EMA + vol_mult + body_frac + bar_range_atr + impulse_pct + retrace-zone + not_too_deep + reclaim + body снова + stop_pct) — конъюнкция убивает частоту → 0 PASS / 398.

## Корректная спека (под подход владельца) — для перестройки Codex
- **Уровни:** реальные горизонтальные S/R (кластеры пивотов, ≥2 касания ИЛИ один сильный объёмный отбой) + наклонные трендлайны. Использовать существующие `sr_levels.py` / `chart_geometry.py` / `router_geometry.py`, не rolling-high.
- **Вход НА ретесте:** входим у уровня ± маленький буфер на возврате цены; НЕ ждём подтверждающий реклейм-бар.
- **Стоп тайтовый** сразу за уровнем (фиксированная малая дистанция, не от плавающего реклейма). **TP перед следующим уровнем**; затем **раннер** на продолжение (отскок → импульсный пробой).
- **Снять лишние фильтры:** оставить объёмный вход + сильный уровень + ретест. Частота вырастет в разы (это и вернёт «как было, когда работало»).
- **Проверка:** через `monthly_analysis` (красный медвежий месяц = FAIL) + `stack_comparison` (голо vs обвязка).
