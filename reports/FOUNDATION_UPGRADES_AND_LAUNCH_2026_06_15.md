# Фундамент: несовершенства → «умнее», двойной тест, и путь к запуску (2026-06-15)

*Синтез за сессию. Фундамент (исполнение/безопасность) здоров; ниже — что сделать УМНЕЕ в обвязке/стратегиях и как безопасно запуститься. Для Codex (зона сервера/монолита).*

## A. Несовершенства фундамента/обвязки (найдено — чинить «умнее»)
1. **Slot-starvation** — allocator отдаёт слоты слабым рукавам, душит сильный (ASB1 соло +$5.47 → в комбо +$0.20). Фикс: **per-sleeve slot-caps** (резерв слота флэт-ядру). Проверять `backtest/stack_comparison.py` на реальном журнале.
2. **Лаговый SMA режим-гейт** — пропускает V-восстановление (нашёл в сценариях Альпаки). Умнее: быстрый ре-вход после washout / бленд 50-200 / breadth-VIX. Через A/B, не вслепую.
3. **Полуручные allowlist'ы** — есть скорер (`strategy_scorer`), но allowlist'ы обновляются полуручно. Умнее: авто-обновление allowlist из скорера (Codex отметил сам).
4. **Слишком строгий вход** — старый аудит: RSI-фильтры режут ~90% лонгов. Это и причина «тонких» WF-окон (мало сделок). Умнее: параметр-плато (не пик!) + param-профили по тирам монет (`bot/param_profiles.py`).
5. **Тайтовые стопы Alpaca intraday** (P0-аналог) — UBER стоп ~0.45% на шуме. Расширить; сверять request_sl ≈ sl на филле.

## B. Двойной тест (обвязка vs голо) — стандарт для каждого кандидата
Инструмент готов: `backtest/stack_comparison.py` (тесты 4/4). Прогон на РЕАЛЬНОМ журнале сервера:
- `HELPS` → обвязка усиливает, ок;
- `HURTS` → **чинить обвязку, не убивать стратегию** (как slot-starvation);
- `BLOCKS ALL` → обвязка слишком строга.
Каждый кандидат в canary должен пройти: голый эдж положительный И обвязка не ухудшает.

## C. Полная цепочка готова (инструменты — моя зона, закрыто)
авто-подбор монет (`strategy_coin_picks`/scorer) → multi-window WF (`crypto_multiwindow_wf`) → мульти-стратегия под авто-подбором (`auto_pick_wf`) → param-профили по тирам (`param_profiles`) → двойной тест (`stack_comparison`) → гейт.

## D. Честный путь к ЗАПУСКУ (что осталось — серверная работа Codex)
Бот уже жив и защищён (flat=0.3, ivb1=0.25). «Настоящий запуск» = первый доказанный карман в малый canary. Шаги:
1. **Расширить data coverage** под авто-пики (1h/4h для ASB1/ARF1, 5m/1h для BREAKDOWN).
2. Перегнать `auto_pick_wf.py` (с param-профилями по тирам).
3. Прогнать `stack_comparison` на журнале → починить обвязку, если душит.
4. **Гейт в live:** только то, что даёт ≥3/4 положительных окна + PF>1 после комиссий + maker-входы.
5. Прошёл гейт → крошечный live risk_mult на $100 → **живые сделки = проба жизни/запуск.**
6. Не прошёл → не крутим риск: шире матрица, параметр-плато, новые рукава по одному.

## E. Принцип запуска
Деньги — только за доказанным эджем. «Запуститься» = включить доказанный карман в малом размере, а не залить капитал в надежду. Это и есть быстрый, но безопасный запуск.
