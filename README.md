# Bybit/Alpaca Adaptive Trading Bot

Живая карта проекта, чтобы не терять контекст между сессиями.

## Главная цель

Собрать портфель стратегий, который:

- торгует достаточно часто, а не раз в месяц;
- проходит честные backtest/WF-проверки на разных фазах рынка;
- умеет снижать риск, когда стратегия или рынок становятся хуже;
- постепенно улучшается через research queue, а не живёт на ручной вере в один удачный прогон.

## Слои системы

- **Стратегии** — конкретные идеи входа/выхода: импульс, пробой, breakdown, отбой от поддержки/сопротивления, флэт, тренд, midterm.
- **Regime orchestrator** — определяет фазу рынка: `bull_trend`, `bull_chop`, `bear_chop`, `bear_trend`; решает, какие семейства стратегий сейчас уместны.
- **Symbol router** — подбирает монеты под конкретные рукава, чтобы стратегия не торговала случайный рынок.
- **Portfolio allocator** — распределяет риск между рукавами и режет риск при пересечении символов/логик. `protective_overlap` означает защитную стрижку риска, а не поломку.
- **Health gate** — не даёт стратегии идти в live, если её свежая статистика плохая, пустая или неподтверждённая.
- **Backtest / WF / dynamic replay** — проверяет стратегию отдельно и весь control-plane стек вместе: комиссии, slippage, режимы, ограничения позиций, роутер, аллокатор.
- **AI operator** — объясняет состояние бота по live snapshot. Он не является источником истины сам по себе; источник истины — файлы runtime и результаты прогонов.
- **Web journal** — визуализация сделок, Alpaca paper ветки, analytics и чат.

## Как доказываем стратегию

Один красивый short-window прогон не считается доказательством.

Минимальный путь к live:

1. Strategy-only backtest: стратегия сама по себе не убыточна.
2. Annual / 360d confirm: годовой прогон с комиссиями и slippage.
3. Walk-forward или stitched dynamic replay: проверка устойчивости по окнам.
4. Full-stack dynamic replay: стратегия проходит вместе с orchestrator/router/allocator.
5. Canary live: маленький риск, отдельная статистика, быстрый kill-switch.

Начиная с 2026-04-23 каждый кандидат должен иметь парную проверку:

- `strategy-only`: голая логика стратегии на тех же данных, комиссиях и slippage.
- `full-stack`: тот же кандидат через regime orchestrator, symbol router, allocator и health gate.

Если `full-stack` оставляет меньше 55% сделок или меньше 45% net P&L от `strategy-only`, это считается не победой стратегии, а задачей на ремонт control-plane. Стек должен доказывать, что он снижает просадку/красные месяцы сильнее, чем убивает частоту и прибыль.

Если стратегия хорошо выглядит отдельно, но ломается в full-stack, это не обязательно значит, что она плохая. Это значит, что надо чинить одно из трёх:

- режим, в котором её включают;
- символы, которые ей дают;
- саму логику входа/выхода.

## Частота входов

Частота — отдельный KPI, но она не должна покупаться ценой минусового edge.

Рабочая цель:

- сначала найти 3-5 реально плюсовых рукавов;
- потом расширять частоту через независимые логики, а не через ослабление одной стратегии до мусора;
- следить за `trades/month`, `PF`, `drawdown`, `negative_months` и `max_negative_streak` вместе.

## Veles vs наш бот

Veles — готовая платформа для DCA/grid/signal-ботов, где можно настраивать одиночные сделки, сетки усреднения, лонг/шорт, индикаторные входы и TradingView alerts.

Наш бот сложнее как исследовательская и портфельная система:

- у нас есть собственные стратегии и code-level логика;
- есть regime orchestrator, router, allocator и health gate;
- можно тестировать весь стек задним числом, а не только один DCA/grid шаблон;
- можно писать новые стратегии и проверять гипотезы глубже.

Но сложнее не значит автоматически прибыльнее. Veles может быть полезен как внешний контрольный стенд для простых сигналов: если стратегия сводится к TradingView alert / indicator / DCA, её можно попробовать повторить там и сравнить исполнение. Если стратегия зависит от нашего router/allocator/regime-stack, Veles её полностью не повторит.

## Текущий принцип

Не верим красивым цифрам без контекста. Нам нужен портфель, который выживает в полном replay, а не стратегия, случайно выигравшая короткое окно.

# v28_19_debug_tools (v2)

Эти скрипты **не являются ботом**. Это утилиты для анализа CSV (trades*.csv) и точечной визуализации сделок.

## 1) Где брать CSV
CSV создаются вашим ботом после прогонов:
- `backtest_runs/<run_id>/trades_inplay.csv`
- `backtest_runs/<run_id>/trades_bounce.csv`
- `backtest_runs/<run_id>/trades.csv` (портфель)

`<run_id>` — папка прогона (например `20260206_154455_inplay_runner_30d_baseline`).

## 2) Примеры запуска

### Top/killers по CSV
```bash
python3 scripts/analyze_trades_csv.py /ABS/PATH/backtest_runs/<run_id>/trades_inplay.csv --top 15
python3 scripts/analyze_trades_csv.py /ABS/PATH/backtest_runs/<run_id>/trades_inplay.csv --symbol DOTUSDT
python3 scripts/find_killers.py /ABS/PATH/backtest_runs/<run_id> --top 15
```

### Плот одной сделки (Bybit public klines)
```bash
python3 scripts/plot_trade_bybit.py --symbol DOTUSDT --entry_ts 1738871100000 --exit_ts 1738875300000 --tf 5 --pad_bars 200
```

## 3) Если ругается на зависимости
Эти утилиты используют только стандартную библиотеку + matplotlib (для plot):
```bash
python3 -m pip install matplotlib
```

## 4) Важно
`bash scripts/run_core_suite.sh ...` запускается **внутри репозитория бота**, а не в папке debug_tools.
