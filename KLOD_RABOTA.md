## 2. Альпака: диагноз закрыт, лечится двумя строками

Твой вывод с сервера дал ответ полностью.

```
grep -c "_default_broker_protection_tif"  →  2      ← починка НА СЕРВЕРЕ ЕСТЬ
ALPACA_BROKER_PROTECTION_ORDER_CLASS=simple_stop     ← переармирование активно
ALPACA_BROKER_PROTECTION_TIF=day                     ← ЭТО ОНО
ALPACA_NATIVE_TRAIL_ENABLE=1                         ← биржевой трейлинг ВКЛЮЧЁН
ALPACA_NATIVE_TRAIL_TIF=day                          ← И ЭТО ТОЖЕ ОНО
ALPACA_NATIVE_TRAIL_REQUIRED=0                       ← сбои молчат
```

Подтвердилась моя версия B. Кодекс написал защиту как **значение
по умолчанию**, а в env стоит **явное** `day` — явное всегда бьёт
умолчание.

**И вторая находка, которой я раньше не видел: биржевой трейлинг
у нас уже включён.** Но у него тоже `TIF=day`, поэтому он умирает
в 20:00 UTC вместе со всем остальным. Мы платили за трейлинг всё
это время и не получали его.

### Виновник назван поимённо

Из твоего крона:

```
*/30 13-20 * * 1-5 ... run_alpaca_live_v38_once.sh --send-orders   # alpaca_live_v38_manager
```

Минуты 0 и 30, часы 13–20. **20:30 попадает сюда.** А сбросы в выписке
стоят ровно на 20:30:22 и 20:30:23. Совпало до секунды.

Цепочка целиком: рынок закрылся в 20:00 → DAY-стоп истёк → в 20:30
менеджер видит «стопа нет» и ставит новый из плана, вход−5%.

### Лечение

Две строки, `day` → `gtc`. Плюс `REQUIRED=1`, чтобы сбои не молчали.

Сначала узнать, в каких файлах они лежат — в выводе блок повторился
трижды, значит копий три:

```bash
ssh -i ~/.ssh/by-bot root@64.226.73.119 \
  'grep -lE "PROTECTION_TIF|NATIVE_TRAIL_TIF" /root/by-bot/configs/*.env'
```

Потом, с копией перед правкой:

```bash
ssh -i ~/.ssh/by-bot root@64.226.73.119 '
  cd /root/by-bot
  mkdir -p backups/env-$(date -u +%Y%m%dT%H%MZ)
  cp configs/<НУЖНЫЕ_ФАЙЛЫ>.env backups/env-$(date -u +%Y%m%dT%H%MZ)/
  sed -i "s/^ALPACA_BROKER_PROTECTION_TIF=day/ALPACA_BROKER_PROTECTION_TIF=gtc/" configs/<ФАЙЛЫ>.env
  sed -i "s/^ALPACA_NATIVE_TRAIL_TIF=day/ALPACA_NATIVE_TRAIL_TIF=gtc/"           configs/<ФАЙЛЫ>.env
  grep -hE "PROTECTION_TIF|NATIVE_TRAIL_TIF" configs/*.env
'
```

Откат — вернуть файлы из `backups/`. Проверка результата — тот же
read-only прогон: `time_in_force` должен стать `gtc`.

Момент удачный: SAFE_HOLD запрещает входы, значит менять нечего,
кроме защиты.

## 3. Ордерблоки: ты прав, я поставил их не туда

Отвечаю прямо: **следующей работой ордерблоки быть не должны, и это
моя ошибка в прошлом плане.**

Где они сейчас:

- возврат в зону **хуже случайного входа** в 8 ячейках из 12;
- вчерашний полный прогон: шесть конфигураций, **ни одна не проходит
  на обоих окнах**;
- доходность отрицательная на всех трёх таймфреймах.

Значит это **ни денежная нога, ни дополнительный сигнал**. Подключать
неизмеренный детектор к чему бы то ни было нельзя — он не улучшает
решение, он его портит и при этом выглядит умно.

Не проверен пока только один вариант: вход **на самом импульсе**,
а не возврат к нему. Это отдельный эксперимент, и до него надо
чинить движок измерения (перекрывающиеся позиции, выход контроля Б
за окно, паспорт прогона, PIT и поправка на число проверок).

### А вот твоя идея с отрисовкой — отличная, беру

«Пусть система в отчётах на графике рисует, как она видит ордерблоки».

Это ровно правильный инструмент, и я его недооценил. Смысл: **проверка
качества детектора глазами до того, как поверить хоть одному числу.**
Если на картинке блоки строятся криво — никакая σ не спасёт.

Но это инструмент контроля, а не продукт. Делаем его тогда, когда
вернёмся к импульсу. Не сейчас.

```

```

**Замку три дня и он пустой.** Это осиротевший лок, а не работающий
Кодекс. Он блокирует все операции с индексом.

Ветка `codex/dynamic-symbol-filters`: ahead 6, behind 2, грязных 474
(было 393 — растёт).

Но по таблице владения индекс и gates — зона Кодекса, и там же лежит
неснятый инцидент с MT5-токеном: на remote старый коммит с токеном,
поэтому обычный push небезопасен, а `--force-with-lease` требует
отдельного разрешения.

**Я это докладываю, а не делаю.** Кодексу одна команда:

```bash
ls -la .git/index.lock && rm .git/index.lock
```

ДипСик тут прав по факту и не прав по адресу: чинить должен владелец
зоны, иначе мы получим ровно ту параллельную перезапись, ради которой
Кодекс и завёл `ACTIVE_WORK_OWNERSHIP.md`.
