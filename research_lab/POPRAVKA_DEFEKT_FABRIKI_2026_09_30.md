# Поправка к хендоффу 30.09: настоящая причина 8 вердиктов

**Диагноз хендоффа (провал сквозь первую ветку в `fabrika.py:371–386`) — неверен
для этого случая.** У всех восьми пунктов `otpechatok_pri_postanovke = 1:645812`
был записан, значит они шли по второй ветке, где текущий код при `trebuet_priyomki`
ставит `dannye_izmenilis` и НЕ взводит.

Настоящая причина — **демон крутил старый код**:

- `.zamok` записан 2026-09-28 09:35 UTC (старт демона, pid 17629);
- исправление приёмки (коммит 4acaa85) — 2026-09-28 10:04 UTC, через 29 минут;
- Python не перечитывает модуль, демон не перезапускался;
- у всех восьми и у `xauusd_unchanged_replication_v1` стоит поле `dannye_prishli` —
  его ставит только код ДО 4acaa85 (новый ставит `dannye_izmenilis`);
- в отчёте 07:10 нет ключа `zhdut_priyomki`, добавленного в 4acaa85.

## Что исправлено (самопроверка: все 37 строк PASS, мутационная проверка ловит снятие ворот)

1. **Демон останавливается сам, если его код сменился** после запуска
   (`kod_otpechatok`: fabrika.py, mehanizmy.py, все бегуны).
2. **Единые ворота приёмки `mozhno_progonyat`** — проверяются и при синхронизации,
   и в момент выбора прогона. Рынки `gold`, `fx7`, `akcii_pit` и любой пункт
   с `trebuet_priyomki` бегут только если человек принял ИМЕННО текущий отпечаток.
3. Первая ветка больше не проваливается насквозь; защита действует и для пунктов
   с прежним вердиктом; вторая ветка (вердикт с `dannye`) уважает ворота.
4. Последний рубеж: взведённый без приёмки пункт возвращается в BLOCKED_DATA,
   откуда бы он ни пришёл (генератор, старая ветка, ручная правка).
5. Приёмка — отдельный человеческий акт: `fabrika.py --prinyat gold` пишет
   `priyomka.json`. Пункты после приёмки сами в очередь НЕ встают.

`xauusd_unchanged_replication_v1` возвращён в BLOCKED_DATA осознанно. Реальной
опасности он не нёс: `begun=None`, выбрать его прогон было невозможно.

Урок для ловушки №2: объяснение проверять по следам в данных (`dannye_prishli`),
а не по чтению текущего исходника — демон исполнял не тот исходник.
