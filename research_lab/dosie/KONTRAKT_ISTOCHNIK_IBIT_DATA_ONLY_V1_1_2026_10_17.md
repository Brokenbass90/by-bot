# Контракт IBIT/BTC DATA-ONLY — v1.1 (уточнения на intake Codex `a10667a`, 17.10.2026)

Заменяет спорные места v1 (`5a23fc3`). Сигнал ETF_PREMIYA_BTC и его DEV-правило не меняются; всё ниже — семантика источника.

## 1. Время и значение закрытия IBIT
- `ibit_close` = поле `c` дневного бара Alpaca IBIT за сессию D, **feed = SIP** (официальное консолидированное закрытие; 15-мин
  задержка бесплатного SIP допустима). IEX не принимается как закрытие: только диагностическое поле `ibit_close_iex`.
- Метку `t` дневного бара (начало интервала) НЕ использовать как время закрытия. Писать: `bar_t_raw` (как есть),
  `session_close_ts` = время закрытия сессии D по календарю Alpaca (IANA America/New_York), `received_at` = момент получения.
- Значение допустимо, только если `received_at ≥ session_close_ts` и бар принадлежит дате D по NY. Иначе — `NOT_READY`, повтор.

## 2. Сокращённые дни
- Замороженное DEV-правило берёт BTC-референс из бара [15:00,16:00) ET **всегда**; на сокращённых днях это расходится с
  закрытием IBIT в 13:00. v1-строка «[12:00,13:00) ET» **отменяется** (она меняла бы правило).
- Сокращённая сессия: строка пишется по DEV-правилу (паритет с тенью), флаг `sokrashchennyy=true`, исполнение → `NO_SEND`.

## 3. Идентичности (полные sha256, не усечённые)
- `rule_sha` = sha256 точных байтов `research_lab/fabrika/etf_premiya_sobytiya.py` на закреплённом research-коммите.
- `source_sha` (на каждый источник) = sha256 канонического JSON сырого ответа (`sort_keys`, разделители `,` `:`, UTF-8).
- `row_sha` = sha256 канонического JSON строки без самого `row_sha`. Сырые ответы хранятся неизменно рядом.
- Сравнение с тенью Claude: ключ `session`; совпадение `sobytie`, `znak`; `|z − z_тень| ≤ 0.01`.

## 4. Отложенная сверка Massive и восстановление
- Строка решения пишется один раз на сессию (append-only); никогда не переписывается.
- Сверка Massive — отдельная запись QA со ссылкой на `row_sha`: `PENDING_SVERKA` → `SVERKA_PASS` / `DEFECT` (> 0.5 %).
  Отсутствие сверки ≠ PASS.
- Допуск к исполнению фиксируется в момент решения: `FRESH` и `feed=SIP` и `sokrashchennyy=false`. Позднее `DEFECT`
  не отменяет решение задним числом, но считается провалом приёмки (10 сессий без DEFECT) и попадает в отчёт.
- Рестарт: уникальность по `session`; частичная запись хвоста — отбрасывается и повторяется с тем же `session`.
