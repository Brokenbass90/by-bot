# Шаблон досье исполнения (FACTORY → PROVEN CANDIDATE → EXECUTION DOSSIER → CODEX) — v1, 17.10.2026

Досье — контракт между исследованием и исполнением. Фабрика заполняет его для кандидата, прошедшего DEV; статус растёт
вместе с доказательствами. Codex берёт в работу только статус ≥ READY_FOR_ORDERS_OFF.

| статус | условие |
|---|---|
| DRAFT | DEV PASS (+ проверки концентрации/заглядывания) |
| READY_FOR_ORDERS_OFF | репликация PASS или достаточно OOS; источники данных в реальном времени определены |
| READY_FOR_MICRO_LIVE | CONFIRM вперёд PASS + ORDERS_OFF паритет PASS (Codex) + письменное GO владельца |

## Разделы (все обязательны; «UNKNOWN» допустим только с названным блокером)
1. **Идентичность:** гипотеза, prereg, sha правила/кода, коммиты вердиктов.
2. **Сигнал:** точная формула, входные ряды, параметры (замороженные), частота событий.
3. **Время доступности:** когда каждый вход известен в реальности (источник, задержка); момент решения.
4. **Инструмент:** биржа, символ, тип, мин. лот/тик, плечо (если есть), часы торговли.
5. **Исполнение:** тип ордера, вход (время/цена), выход (время/правило), что делать при пропуске окна (NO_SEND).
6. **Размер и риск:** капитал рукава, размер на событие, максимум одновременно, стоп/убыток на событие — **решает владелец**,
   исследование даёт диапазон и расчёт.
7. **Издержки:** модель (bps на круг), фандинг, что проверить на живых квитанциях.
8. **Ожидания и паритет:** распределение исходов в DEV/OOS (среднее, медиана, доля плюсов, худшие 3), что считать совпадением.
9. **Остановка:** детерминированные критерии STOP (деградация, дефект данных, превышение убытка) — без ручного «подождём».
10. **Квитанции:** поля, которые должен писать исполнитель (signal_at, decided_at, entry_at, fill, exit, R, источники, хэши).
11. **Открытые вопросы / блокеры** с владельцем и датой.
