# RESEARCH STATION — дисциплинированный массовый поиск (изолирован от прода)
Директория `research_lab/` НИКОГДА не тащится в прод. Здесь гоняются тысячи вариантов, но выживают
единицы — только те, что прошли ТРОЙНУЮ проверку на невиданных данных.

## Почему просто «прогнать 10k и взять лучшее» = ловушка
Multiple testing: чем больше вариантов, тем больше ЛОЖНЫХ «победителей» по случайности. Защита одна —
кандидат должен выжить на данных, которые поиск НЕ ВИДЕЛ.

## Воронка станции (уже зашита в search_station.py)
1. IN-SAMPLE (часть символов + ранняя половина): grid search -> wf_folds(purge/embargo) + oos_selector
   (hero-rejection) + LOSO(anti-concentration). Проходит ~малая доля.
2. FORWARD-HOLDOUT (поздняя половина тех же символов): иммунитет к search-overfit.
3. OOS-SYMBOL HOLDOUT (символы вне поиска): проверка переносимости.
Только выжившие ВСЕ ТРИ = реальные кандидаты. Демо (att1, 4 комбо): 4->0->0 (режет шум — так и надо).

## Как сделать МОЩНОЙ (Codex, на сервере/Mac, недели)
- Расширить search_space: не только параметры, но и РАЗНЫЕ ЛОГИКИ входа/выхода/фильтров/режимов.
- Много символов (30-50), 3+ года данных (несколько bull/bear/chop циклов).
- Добавить multiple-testing correction: чем больше N протестировано, тем ВЫШЕ порог PF/expectancy
  (deflated Sharpe / Bonferroni-подобная поправка) — сейчас порог фиксированный, ужесточить под N.
- Добавить walk-forward ПО ВРЕМЕНИ форвард-периода (не только пополам), rolling.
- Логировать ВСЕ протестированные (не только выжившие) -> честная статистика ложных срабатываний.
- Прогресс/receipt/автостоп при integrity-fail (как research_nightly).

## Честное ожидание
Даже мощная станция может НЕ найти ничего — если эджа нет в заданном пространстве/данных. Но:
(а) она освобождает от ручного перебора; (б) всё, что выживает тройную проверку, можно ДОВЕРЯТЬ
(в отличие от одно-оконных карманов). Это правильный способ искать, а не гарантия денег.

## Запуск
`PYTHONPATH=. python3 research_lab/search_station.py` (демо att1). Расширять search()/build()/grid.
