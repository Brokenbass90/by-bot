# PREREG LIQ_OTSKOK_4H_V2 — отскок после вынужденных ликвидаций (14.10.2026, Claude CRO). До любых исходов V2.

Семья FORCED_FLOW_LIQ: статус UNKNOWN (DATA_DEFECT, POPRAVKA 12.10) — старый сборщик переворачивал сторону; настоящий отскок
никогда не проверялся. Только на ленте Codex «Bybit liquidation source V2» (`bot/bybit_liquidation_source_v2.py`:
side = long ⇔ S=Buy ⇔ ликвидирован ЛОНГ; usd = qty × bankruptcy price — прокси, не цена исполнения). Сборщик не трогаю.

## Механизм
Ликвидация — принудительная рыночная сделка без информации: биржа закрывает позицию по любой цене. Массовая односторонняя
ликвидация лонгов за час = временное давление продавцов → цена недооценена → отскок за следующие часы (зеркально для шортов).
Поставщик ликвидности, купивший у ликвидатора, получает премию.

## Событие (точно)
- Час h = часовое окно UTC [h, h+1ч). L_long(s,h) = Σ usd ликвидаций side=long с T ∈ [h, h+1ч) (T — время события биржи,
  НЕ время приёма); L_short аналогично.
- LONG_LIQ: L_long ≥ $50 000 И L_long ≥ 99-й перцентиль L_long этой монеты по часам предыдущих 14 суток ленты V2
  (прогрев 14 сут.; часы без ликвидаций = 0) И L_long ≥ 3 × L_short.  → ЛОНГ.   SHORT_LIQ — зеркально → ШОРТ.
- Причинность: решение в h+1ч + 2 мин (запас на доставку ленты: событие учитывается, только если recv_ts ≤ h+1ч+2мин;
  поздние — отбрасываются и считаются в QA).
- Вход: цена открытия 1-мин свечи Bybit linear в h+1ч+2мин. Выход: через 4 ч (открытие 1-мин свечи h+5ч+2мин). Без стопов.
- По монете не более одной позиции; событие во время открытой позиции монеты не берётся.
- Издержки: 12 bps круг (тейкер + проскальзывание, как у всех крипто-тестов) + фактический фандинг Bybit, если 4 ч пересекают
  момент фандинга. Цены и фандинг судья берёт из публичного API Bybit ПОСЛЕ закрытия окна.
- Вселенная: все USDT-перпы, на которые подписан сборщик V2 (фиксируется в квитанции сборщика); монеты без 14 сут. ленты — нет.

## Базовая форма и один механистический претендент
- BASE: все события выше.
- DISLOK (претендент): BASE, где цена за час h сдвинулась ПО направлению ликвидации ≥ 2 sd часовых доходностей монеты за
  168 предыдущих часов (давление видно в цене — механизм говорит, что отскок должен быть сильнее). Других вариантов нет.

## Кластеризация и независимость
- Волна ликвидаций бьёт по многим монетам в один час → t считается по кластерам «4-часовой блок UTC входа» (среднее по событиям
  блока), Ньюи–Уэст лаг 1.
- До PnL (без доходностей): ранговая корреляция стороны события с рангом KITY m3 последнего недельного сигнала;
  |корр.| > 0.5 → снять как дубликат KITY.

## Ворота источника (до PnL — НЕ смотреть исходы, пока не выполнены)
1. ≥ 200 событий BASE после прогрева, из ≥ 20 разных суток и ≥ 15 монет.
2. QA ленты V2: нет дыр > 10 мин без heartbeat; дубликаты по raw_item_canonical_sha256 = 0 после дедупликации; T в мс;
   доля поздних (recv − T > 2 мин) < 5%.
3. Проверка семантики стороны (без доходностей будущего): в событиях LONG_LIQ доходность ТОГО ЖЕ часа h < 0 у ≥ 70% событий,
   в SHORT_LIQ > 0 у ≥ 70%. Иначе — STOP (дефект стороны), PnL не смотрится.

## Реестр и критерий
- Окно LIQ_V2_DEV (роль DEV): от конца прогрева до выхода 200-го события BASE; бюджет 2 (BASE + DISLOK), α 0.20.
- SCREEN PASS (BASE): средний net > 0, t ≥ t_req реестра (k = 2), обе половины по времени > 0. DISLOK засчитывается, только если
  сам проходит тот же критерий; иначе — информативен только знак разницы.
- PASS → следующее окно CONFIRM (новые события после DEV, одна попытка, α 0.05, ≥ 200 событий) → только потом досье на деньги.
- FAIL → причинный постмортем; спасение ≤ 1 причинный вариант (протокол). Повторный просмотр тех же событий запрещён.
