# PREREG POLY_NO_SEREDINA_ISTORIYA — честная проверка механизма POLY_YES_PEREPLATA на непросмотренной части истории (22.10.2026, до расчёта)

## Зачем и почему это честно
Тень POLY_YES_PEREPLATA (покупать NO на лестницах «крипто выше X») придумана по калибровке хвостов истории (итог
POLY_FAVORIT_SUTKI, 19.10): там исходы смотрелись **только** у рынков с ценой YES в [0.05; 0.20] и [0.80; 0.95] за сутки до расчёта.
Рынки с ценой YES в **(0.20; 0.80)** по исходу не разбирались ни разу (QA-сверка источников 19.10 шла только по хвостам — `main()` →
`qa(sdelki)`). Это 621 рынок, 449 событий, 302 даты, 09.2025–09.2026 (подсчитано до исходов, только по ценам).
Ограничение, раскрываю: это те же события (актив + дата), что и в хвостах; исходы хвостов этих событий были видны.

## Правило (заморожено, без перебора)
- Разбор рынков — `polymarket/poly_favorit_sutki.py: rynki()` без изменений: закрытые `kripto_cena`, вопрос «Will the price of
  Bitcoin|Ethereum|Solana|XRP be above $X on <дата>?», T = расчёт − 24 ч, p = последняя точка ряда YES с t ≤ T не старше 6 ч, есть
  точки после T.
- Отбор: 0.20 < p < 0.80.
- Сделка: купить NO по q = (1 − p) + c, c = 0.01; комиссия Polymarket 0.07 · q · (1 − q) на токен (всегда, т.к. признак комиссии на
  истории неизвестен). Стресс: c = 0.02 и ставка 0.10. Доход = (выплата NO − (q + комиссия)) / (q + комиссия).
- Исход — `ishod()` без изменений (Bybit h1, полоса 0.3 %, иначе финальная цена Polymarket ≥ 0.98 / ≤ 0.02, иначе исключить).
  Ворота данных: совпадение Bybit и Polymarket на этом отборе ≥ 97 % (конвенция времени — та, что даёт большее совпадение, как 19.10).

## Вывод и критерий
Единица — событие (среднее по рынкам события). t по событиям и t по датам расчёта (все события даты — один кластер).
PASS = среднее > 0, t по событиям ≥ порога окна реестра, t по датам ≥ 2.0, обе половины по времени > 0, стресс > 0.
FAIL = среднее ≤ 0. Иначе INCONCLUSIVE. Описательно: калибровка по корзинам 0.20–0.35 / 0.35–0.50 / 0.50–0.65 / 0.65–0.80.
Смысл: PASS — историческая поддержка механизма, **не замена** тени вперёд; правила и сроки тени не меняются, доход тени не открывается.
FAIL — механизм не подтверждён на середине лестницы; тень продолжается до своего вердикта (её диапазон шире).
Ограничение: на истории нет стакана — цена из ряда сделок, спред моделируется c; ёмкость не проверяется.
