# Предрегистрация: MPL, вскрытие двумя руками
Объявлено 12 августа 2026 ДО вскрытия. Заменяет процедурную часть
PREREG_MPL_V3_2026_08_12.md; пороги входа не меняются.

## Почему две руки, а не одна

Разбор стопов на предхолдаутных данных (2023-01..2025-09) показал:

```
58% выбитых сделок цена возвращает ко входу за сутки, медиана 4.2 часа
24% стопов случились после хода в плюс больше чем на целый риск
21% дошли до половины пути к цели и развернулись
медианный ход в плюс перед выбиванием: 0.45R
```

При стопе вдвое шире винрейт 42% -> 51%, и, что важнее, издержки
в долях R падают вдвое (0.072 -> 0.036), потому что при том же риске
в деньгах позиция вдвое меньше, а комиссия платится с позиции.

Запечатанный период один. Вскрывать его на настройке, которую мы сами
считаем худшей, — расточительство. Молча подменить правило после
диагностики на тех же данных — подгонка. Поэтому обе руки объявлены
здесь, до вскрытия, и считаются одним прогоном.

## Руки

```
ГЛАВНАЯ   V4   всё как в V3, но стоп = вход - 2.0 * (вход - стоп_V3)
ВТОРАЯ    V3   исходный стоп
```

Кроме множителя стопа не меняется НИЧЕГО: отбор, импульс, откат,
расстояние до уровня, цель, правило продления, издержки, универсум.

Множитель 2.0 выбран как середина ровного участка (x1.5, x2.0, x3.0
дают +0.059, +0.058, +0.048 при уровне шума около 0.03R и потому
неразличимы), а не как максимум.

## Проверка правила продления при новом стопе

Требование предрегистрации V3 — частота срабатывания в коридоре
5-50%. Проверено до вскрытия:

```
стоп x1.0  ->  8%      стоп x2.0  ->  13%
стоп x1.5  -> 11%      стоп x3.0  ->  15%
```

При x2.0 частота 13%, коридор соблюдён. Период EMA НЕ меняется,
разрешение из V3 на его пересчёт не используется.

## Поправка на две проверки

Нижняя граница блочного бутстрапа берётся как **1.25-й процентиль**
вместо 2.5-го. Это соответствует уровню 95% на семейство из двух
гипотез (Бонферрони). Все остальные ворота — без изменений.

## Критерии смерти (для каждой руки отдельно)

* средний R после издержек <= 0
* превышение над случайным входом < 0.05R
* сделок меньше 150

## Критерии приёмки (для каждой руки отдельно)

* R > 0
* превышение над случайным входом > 0.05R
* нижняя граница бутстрапа (1.25-й процентиль) > 0
* сделок >= 150
* все три календарных квартала положительны
* обе половины периода положительны и ни одна не хуже -0.02R

## Решение, объявленное заранее

```
V4 прошла, V3 нет   -> принимаем V4
обе прошли          -> принимаем V4
только V3 прошла    -> принимаем V3
ни одна не прошла   -> MPL закрывается
```

Даже принятая рука идёт НЕ в деньги, а в теневой сбор до 30-50
проспективных закрытых сделок.

## Запрещено

Любое изменение после вскрытия. Третья рука не добавляется.
Вскрытие одно, результат write-once.

## Исполнение

```
python3 research_lab/mpl_v4_holdout.py research_lab/data/m15_exec_v3 \
    --owner-authorization owner-explicit-2026-08-12
```

Скрипт — версия Codex `mpl_v3_holdout.py` с минимальной правкой:
добавлен множитель стопа, квантиль бутстрапа вынесен в параметр,
main считает обе руки и печатает объявленное решение. Вся защита
(preflight без открытия данных, проверка целостности, write-once,
токен владельца, цензура конца окна) сохранена без изменений.

До декодирования NPZ manifest фиксирует SHA256 каждого из 62 файлов,
SHA256 build-status, кода, allowlist и этой предрегистрации. После расчёта
все хэши сверяются повторно; drift оставляет только unseal-manifest и не
позволяет записать result. Любой существующий manifest или result запрещает
повторный запуск: после начала вскрытия holdout считается потраченным даже при
аварийном завершении.
