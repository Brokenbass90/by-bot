# PREREG ALPACA H2b — устойчивость рейтинга, только вперёд (19.10.2026, ДО первого нового наблюдения)
Основание: H2 STAB21 — EXPLORATORY_LEAD на горизонте 42 сессии (ALPACA_SMART_SELECTION_V1_VALIDACIYA_2026_10_19).
Исторические данные по 2026-09-04 для вердикта H2b НЕ используются. Денежная Monthly не меняется.

## Заморожено
- Признак STAB21: доля из последних 21 сессии (включая сигнальную), когда бумага была в top-18 по `_universe_health`
  И проходила `_v38_candidate` (backtest/alpaca_honest_portfolio.py, как в коммите d1fab6e); код `alpaca_smart_v1.stab21`.
- Baseline: замороженный `select_v38_successor`; вселенные U2 (фильтр U2 из a212281) и U58 — раздельно.
- Снимки (PIT, ежедневно после закрытия): по каждой допустимой бумаге — здоровье, место, прошёл ли сетап, оценка кандидата,
  STAB21, включая отвергнутых; файл дня неизменяемый, с SHA; пропущенный день не восстанавливается задним числом.
- Единица вывода: месячные сигнальные даты Monthly (как в H2), горизонт 42 сессии, доходность от открытия сессии входа.
  Дневные снимки — для аудита и отчётности, не для увеличения числа наблюдений.

## Метрики и решение
ГЛАВНАЯ (A): Rank IC STAB21 в широком пуле top-100 по здоровью (больше бумаг на дату → меньше шум).
ВТОРАЯ (B): Rank IC STAB21 в пуле top-18 (как в H2).
k = 2 → t_req = 2.24; t — Ньюи–Уэст, лаг 2, по месячным датам; подтверждение — moving-block bootstrap (блок 4).
Вердикт — по каждой вселенной отдельно:
- первая оценка не раньше 18 месячных дат с завершённым 42-сессионным исходом; до этого — только проверка качества данных;
- PASS: (A) t ≥ 2.24 и среднее IC > 0 и бутстреп-CI выше 0;
- FAIL: на 18-й дате среднее IC(A) ≤ 0; или к 36-й дате нет PASS;
- иначе INCONCLUSIVE до 36-й даты (одна промежуточная оценка на 27-й дате с тем же порогом).
Портфель (отчётно, без права вердикта): теневые книги BASE и H2 (z-сумма, как в H2) по каждой вселенной, 20 bps.
PASS H2b не меняет Monthly: для этого нужен отдельный change request с портфельным подтверждением и GO владельца.
