# PREREG BTC_ETH_SREDNESROK_OTKAT — откат к EMA20 по 4h-тренду на BTC/ETH (22.10.2026, до прогона)

## Зачем
Владелец спросил: «а что со среднесрочными крипто-стратегиями на BTC/ETH?». В репозитории есть четыре таких стратегии
(`btc_eth_midterm_pullback`, `_v2`, `btc_eth_midterm_v3`, `btc_eth_midterm_short_v1/_v2`), в инвентаре кода у всех статус NE_PROVERENO.
Честной проверки не было.

## Что нашёл при ревью кода (до прогона)
1. **Название вводит в заблуждение.** Это не среднесрок, а внутридневной свинг: тайм-стоп 84 пятиминутки ≈ 7 часов, не больше одного
   сигнала в день, вход по 1h, фильтр тренда по 4h.
2. **Дефект в старых прогонах (11.08.2026, `backtest_runs/*MT-btc_eth_midterm_*-mt20`).** Стратегия ставит стоп от ATR(14) часовика
   (1.2 ATR1h), а трейлинг в движке (`backtest/portfolio_engine.py`, `_atr(sym, period)` на `exec_candles`) считает ATR по
   **5-минутным** свечам и включается с первого бара. Трейлинг 1.1 × ATR5m примерно в 3–4 раза уже исходного стопа, и сделку выбивает
   за минуты. По файлам сделок: медиана удержания 0.2 ч у всех пяти версий; BTC+ETH: pullback n=198, средний −0.095R; v2 n=112, −0.153R;
   v3 n=40, −0.103R. **Старые прогоны проверяли дефект, а не идею.** Без этого исправления их минус ничего не говорит о стратегии.
3. Причинность: `KlineStore._slice` отдаёт только закрытые бары (`_completed_end`), заглядывания в будущее по старшим ТФ в движке нет.
4. Параметры по умолчанию подбирали в феврале–марте 2026 (`f03e4a2`, `f0cf522`, `ba716e0` «Tune/Retune») на этой же истории. Поэтому
   окно — только DEV: даже плюс здесь не доказательство, а повод для forward-тени.

## Правило (одна версия: параметры по умолчанию из кода, без перебора)
- Сигналы: код `strategies/btc_eth_midterm_pullback.py` без изменений, конфиг по умолчанию, BTCUSDT и ETHUSDT, лонг и шорт.
  Стратегия вызывается на каждой закрытой 5m-свече; 1h и 4h свечи собираются из 5m по UTC, отдаются только закрытые.
- Вход: открытие следующей 5m-свечи. Стоп и цели — цены из сигнала (стоп 1.2 ATR1h или за свинг; TP1 1.2R на 50%, TP2 2.6R на остаток).
- **Основная версия A (замысел автора):** трейлинг 1.1 × ATR(14) **часовика** от лучшей цены с момента входа, пересчёт на закрытии
  каждого часа, только в сторону сделки. Тайм-стоп: выход по закрытию 84-й 5m-свечи. Стоп и тейк в одной свече → сначала стоп.
- Описательные версии (не критерий): B — как в движке (трейлинг 1.1 × ATR(14) по 5m с первого бара, воспроизведение дефекта);
  C — без трейлинга (только стоп, TP1/TP2 и тайм-стоп).
- Позиции по BTC и ETH независимы (по одной на монету). R = результат / (вход − стоп) на долю позиции.
- Расходы: 6 bps комиссия + 2 bps проскальзывание на каждую сторону (тейкер Bybit 0.055% ≈ 6 bps). Фандинг не учитываю: удержание
  ≤ 7 ч, максимум одно начисление.
- Окно: KRIPTO_H1M5_2023_2026Q3, данные 5m Bybit 05.07.2023–04.07.2026 (кэш `.cache/klines/*_5_1688515200000_1783123200000.json`),
  первые ~45 дней — прогрев 4h EMA200.

## Контроль и критерий (заморожены)
- Контроль: для каждой сделки 20 случайных входов (сид 20261022) той же монеты и стороны в том же календарном месяце, в часы, где
  4h-фильтр тренда даёт ту же сторону. Стоп = 1.2 ATR1h, цели и выход — как в версии A.
- Метрика: превышение среднего R над контролем; t с кластерами по неделям входа.
- PASS = средний R версии A после расходов > 0, превышение > 0, t ≥ порога окна (реестр: k попыток на окне, α 0.20), обе стороны
  (лонг и шорт) ≥ 0 либо одного знака. Иначе FAIL; при n < 100 — INCONCLUSIVE.
- При PASS — только forward-тень, никакого LIVE и никакой подстройки. При FAIL — остальные версии (v2, v3, short_v1/v2) я **не**
  прогоняю отдельно по этому окну: они того же механизма, а окно и так многократно просмотрено.
- Деньги: при риске 0.5% депозита на сделку — % в год = средний R × сделок в год × 0.5%; в $ — на депозит $1000.
