## 1. Холодный старт ноги (n_s < 2 на cutoff сгиба)
Это не новое правило, а значение формул V1 §4 при нулевых данных:
- n_s = 0 → μ̂_s = 0·m/(0+κ0) = 0; при n_{s,c} = 0 → μ̂_{s,c} = (0 + κ1·0)/(0 + κ1) = 0. Числитель z равен нулю при любом σ̂ > 0.
- Поэтому: **если n_s < 2 (σ̂_s не определено) или σ̂_s = 0 → z := 0, mult = 1.0.** Ячейки этой ноги не считаются.
- Нога НЕ исключается (P2): участвует во всех трёх руках с теми же лимитами, в BRAIN_DET — в порядке (−z, t_available, id) с z = 0.
- Статистика будущих сгибов не используется. Правило A5 §1 «откат без контекста» = ровно этот случай.
- В отчёт: по каждому сгибу список ног в холодном старте и их число сделок в test.

## 2. Фандинг на истории: время и календарь (только из самого файла, без подстановки нуля)
**Время.** Ставка расчёта считается известной в момент расчёта s (timestamp файла). Решения её не используют: по A3 фандинг входит
в net USD и в E только при release_time, а учитываются расчёты τ < s ≤ release_time, т.е. всегда s ≤ момента зачисления.
Время публикации поэтому не нужно; заглядывания вперёд нет.

**Календарь (доказательство полноты для удержания (τ, release_time]).** S — отсортированные расчёты символа в data/pit_daily/<SYM>.json.
Удержание ПОКРЫТО ⇔ одновременно:
1. есть s_a ∈ S с s_a ≤ τ и s_b ∈ S с s_b ≥ release_time (файл охватывает удержание);
2. все ставки на (τ, release_time] конечны;
3. локальный шаг g₀ = медиана последних 10 интервалов S, заканчивающихся на s_a (только прошлое к τ; если интервалов < 10 →
   не покрыто), и каждый интервал между соседними расчётами на [s_a, s_b] ≤ g₀.

Иначе сделка = FUNDING_UNKNOWN по A4: риск занимает и освобождается по расписанию, в E и метрики не идёт, считается отдельно.
Ошибка правила 3 возможна только в консервативную сторону (смена на более редкий шаг внутри удержания → UNKNOWN, не ноль).

**Нет файла символа (HFTUSDT и любые другие):** все его сделки — FUNDING_UNKNOWN. Ноль не подставляется, символ не исключается.

**Порог (A3 §4/A4 §3 без изменений):** доля FUNDING_UNKNOWN > 5% сделок в любой руке → BLOCKED_DATA.
В отчёт: доля UNKNOWN по руке, по причине (нет файла / дыра в календаре / мало истории / нечисловая ставка) и топ символов.
